# 제1부 — 데이터셋 결함 (2건)

큰 연산자 `∑` / `∏` 의 본문 우선순위 문제다. mathlib 의 notation 은

    notation3 "∑ " (...) " ∈ " s ", " r:67 : (scoped f => Finset.sum s f) => r

본문 `r` 을 **우선순위 67** 로 파싱한다. `+` 는 `infixl:65` 이므로 65 < 67 이라
본문에 들어가지 못하고 **합 바깥으로 빠진다**. `*` 는 `infixl:70` 이라 들어간다.

    ∑ k ∈ Finset.range 8, 2 * k + 1
      = (∑ k ∈ Finset.range 8, 2 * k) + 1        ← Lean 이 읽는 방식
      ≠ ∑ k ∈ Finset.range 8, (2 * k + 1)        ← 사람이 의도한 방식

Lean 으로 확인:

    (∑ k ∈ Finset.range 8, 2 * k + 1)   = 57   ✅ 통과
    (∑ k ∈ Finset.range 8, (2 * k + 1)) = 64   ✅ 통과

둘 다 통과한다는 것이 두 식이 서로 다른 값임을 증명한다.
(2·(0+…+7) = 56, +1 → 57.  의도했던 1+3+…+15 = 64.)

## 1.1 `mathd_numbertheory_343` — 원 문제가 거짓이다

**원 문제 (사람 말)**
> 0 과 12 사이의 모든 홀수의 곱의 일의 자리 숫자는 무엇인가? 5 임을 보여라.
> 즉 1·3·5·7·9·11 = 10395 의 일의 자리는 5.

**데이터셋의 형식화**
```lean
theorem mathd_numbertheory_343 : (∏ k ∈ Finset.range 6, 2 * k + 1) % 10 = 5 := by
```

**Lean 이 실제로 읽는 것**
```lean
((∏ k ∈ Finset.range 6, 2 * k) + 1) % 10 = 5
```

`k = 0` 항이 `2 * 0 = 0` 이므로 곱 전체가 **0** 이다. 따라서 좌변은
`(0 + 1) % 10 = 1` 이고, 주장은 `1 = 5` 가 된다.

**Lean 판정**

    (∏ k ∈ Finset.range 6, 2 * k + 1) % 10 = 5      ❌ decide: "proved that the proposition is false"
    (∏ k ∈ Finset.range 6, (2 * k + 1)) % 10 = 5    ✅ 통과
    (∏ k ∈ Finset.range 6, 2 * k) = 0               ✅ 통과
    (∏ k ∈ Finset.range 6, 2 * k + 1) = 1           ✅ 통과
    ¬ ((∏ k ∈ Finset.range 6, 2 * k + 1) % 10 = 5)  ✅ 통과   ← 부정이 증명된다
    (∏ k in Finset.range 6, 2 * k + 1) % 10 = 5     ❌ 거짓 (구 `in` 표기도 동일)

**이 문제는 증명 불가능하다.** 우리 마이그레이션(`in` → `∈`)의 문제도 아니다
— 구 표기에서도 똑같이 거짓이다. miniF2F 원본의 형식화 오류다.

**스케치가 한 일**
```lean
theorem mathd_numbertheory_343 :
    (∏ k ∈ Finset.range 6, 2 * k + 1) % 10 = 5 := by
  have h_mod : (∏ k ∈ Finset.range 6, 2 * k + 1) ≡ (1 * 3 * 5 * 7 * 9 * 1) [MOD 10] := by
    sorry
  have h_eq_mod : (∏ k ∈ Finset.range 6, 2 * k + 1) % 10
                = (1 * 3 * 5 * 7 * 9 * 1) % 10 := h_mod.mod_eq
  have h_rem : (1 * 3 * 5 * 7 * 9 * 1) % 10 = 5 := by norm_num
  simpa [h_rem] using h_eq_mod
```

스케치 자체는 **수학적으로 훌륭하다.** 곱을 mod 10 의 잉여로 바꾸고
(11 ≡ 1 이므로 마지막 항을 1 로 대체), 잉여의 곱을 계산해 5 를 얻는 정석
풀이다. 조립도 맞다. `h_mod` 만 참이면 완결된다.

그런데 `h_mod` 의 좌변은 1, 우변은 945 이고 mod 10 에서 1 ≢ 5 다.
**목표가 거짓이니 h_mod 도 거짓이다.** 149회를 여기에 썼다.

## 1.2 `mathd_algebra_158` — 원 문제가 공허하게 참이다

**원 문제 (사람 말)**
> 연속한 짝수 5개의 합은 처음 8개의 연속한 홀수의 합보다 4 작다. 이때
> 가장 작은 짝수는 8 임을 보여라.
> 의도: (1+3+…+15) − (a + (a+2) + … + (a+8)) = 4, 즉 64 − (5a+20) = 4 → a = 8.

**데이터셋의 형식화**
```lean
theorem mathd_algebra_158 (a : ℕ) (h₀ : Even a)
    (h₁ : ↑(∑ k ∈ Finset.range 8, 2 * k + 1) - ↑(∑ k ∈ Finset.range 5, a + 2 * k) = (4 : ℤ)) :
    a = 8 := by
```

**Lean 이 실제로 읽는 것**

좌변의 합은 앞서 본 대로 57 이다. 오른쪽 합은 더 심하다.

```lean
∑ k ∈ Finset.range 5, a + 2 * k
  = (∑ k ∈ Finset.range 5, a) + 2 * k      -- 본문은 `a` 뿐, `+ 2 * k` 가 빠져나온다
  = 5 * a + 2 * k                          -- 이때 k 는 바인더 밖의 자유변수!
```

`k` 가 바인더를 벗어나 자유변수가 되고, Lean 의 auto-bound 기능이 이를
정리의 암묵 인자 `{k : ℕ}` 로 자동 추가한다. 즉 실제 정리는 이것이다.

```lean
theorem mathd_algebra_158 {k : ℕ} (a : ℕ) (h₀ : Even a)
    (h₁ : (57 : ℤ) - ((5 * a + 2 * k : ℕ) : ℤ) = 4) : a = 8
```

이것이 잔여 목표로 직접 확인된다.

    example : (∑ k ∈ Finset.range 5, 8 + 2 * k) = 60 := by decide
      ❌ 실패,  잔여 목표  ⊢ 57 - (40 + 2 * ↑k) = 4        ← k 가 살아 있다
    example : (∑ k ∈ Finset.range 5, (8 + 2 * k)) = 60 := by decide
      ✅ 통과

**그래서 가설이 모순이다.** `h₁` 은 `5a + 2k = 53` 을 뜻한다. 좌변은
`5a` 와 `2k` 의 합인데 `h₀ : Even a` 이므로 `5a` 는 짝수, `2k` 도 짝수,
합은 짝수다. 53 은 홀수이므로 만족하는 `(a, k)` 가 없다.

가설이 모순이면 결론은 무엇이든 따라온다. **이 정리는 공허하게 참이며
세 줄로 증명된다.**

```lean
theorem mathd_algebra_158 (a : ℕ) (h₀ : Even a)
    (h₁ : ↑(∑ k ∈ Finset.range 8, 2 * k + 1) - ↑(∑ k ∈ Finset.range 5, a + 2 * k) = (4 : ℤ)) :
    a = 8 := by
  simp [Finset.sum_range_succ] at h₁
  obtain ⟨m, hm⟩ := h₀
  omega
```
    ✅ 통과 — Lean 으로 확인

**스케치가 한 일**
```lean
have h_sum₁ : (∑ k in Finset.range 8, 2 * k + 1) = 64 := by       -- ← 거짓 (57 이다)
  norm_num [Finset.sum_range_succ, ...] <;> rfl

have h_sum₂ : (∑ k in Finset.range 5, a + 2 * k) = 5 * a + 20 := by  -- ← 거짓 (5a + 2k 다)
  simp [Finset.sum_range_succ, ...] <;> ring_nf <;> norm_num <;> omega

have h_main : (5 : ℕ) * a + 20 = 60 := by
  have h₂ : (↑(∑ k in Finset.range 8, 2 * k + 1) : ℤ) - ↑(∑ k in Finset.range 5, a + 2 * k) = 4 := h₁
  rw [h_sum₁] at h₂
  rw [h_sum₂] at h₂
  norm_cast at h₂ <;> (try omega) <;> ...
```

스케치는 **사람이 의도한 수학을 정확히 따라갔다.** 64 − (5a+20) = 4 → 5a = 40
→ a = 8. 문제는 그 64 와 5a+20 이 **Lean 이 읽는 식의 값이 아니라는 것**이다.
`h_sum₁`, `h_sum₂` 둘 다 거짓이므로 143회를 시도해도 닫히지 않는다.

**역설적인 지점** — 이 정리는 실제로 증명 가능하다(공허하게). 그런데
HILBERT 는 "수학적으로 올바른" 경로를 따라갔기 때문에 실패했다. 가설이
모순임을 알아채는 경로는 시도하지 않았다.

## 2.1 `aime_1984_p7` — 산술 오류

**원 문제 (사람 말)**
> f : ℤ → ℤ 가 n ≥ 1000 일 때 f(n) = n − 3, n < 1000 일 때 f(n) = f(f(n+5)) 를
> 만족한다. f(84) 를 구하라. 답은 997.

**원 문제 (Lean)**
```lean
theorem aime_1984_p7 (f : ℤ → ℤ) (h₀ : ∀ n, 1000 ≤ n → f n = n - 3)
    (h₁ : ∀ n, n < 1000 → f n = f (f (n + 5))) : f 84 = 997 := by
```

**스케치가 만든 서브골**
```lean
theorem h997_aime_1984_p7 (f : ℤ → ℤ)
    (h₀ : ∀ n, (1000 : ℤ) ≤ n → f n = n - 3)
    (h₁ : ∀ n, n < (1000 : ℤ) → f n = f (f (n + 5)))
    (h1000 : f (1000 : ℤ) = 997) (h1002 : f (1002 : ℤ) = 999)
    (h1004 : f (1004 : ℤ) = 1001) (h1001 : f (1001 : ℤ) = 998)
    (h1003 : f (1003 : ℤ) = 1000) :
    f (997 : ℤ) = 997 := by
```

**어디가 거짓인가**

f(997) 을 직접 전개하면

    f(997) = f(f(1002))        (997 < 1000)
           = f(999)            (f(1002) = 1002 − 3 = 999)
           = f(f(1004))        (999 < 1000)
           = f(1001)           (f(1004) = 1004 − 3 = 1001)
           = 998               (1001 ≥ 1000 이므로 1001 − 3)

즉 **f(997) = 998 이고 997 이 아니다.**

    f 997 = 998   ✅ 통과
    f 997 = 997   ❌ 실패 ("omega could not prove the goal")

이 함수의 알려진 성질은 n < 1000 에서 **n 이 홀수면 998, 짝수면 997** 이다.
997 은 홀수다. 스케치는 문제의 최종 답 997 을 중간 단계 f(997) 의 값으로
그대로 옮겨 썼다. 이름이 `h997` 인 것이 그 혼동을 드러낸다.

## 2.2 `algebra_cubrtrp1oncubrtreq3_rcubp1onrcubeq5778` — 가설 누락

**원 문제 (사람 말)**
> 실수 r 이 r^(1/3) + 1/r^(1/3) = 3 을 만족한다. r³ + 1/r³ = 5778 임을 보여라.

**원 문제 (Lean)**
```lean
theorem algebra_cubrtrp1oncubrtreq3_rcubp1onrcubeq5778 (r : ℝ)
    (h₀ : r ^ ((1 : ℝ) / 3) + 1 / r ^ ((1 : ℝ) / 3) = 3) : r ^ 3 + 1 / r ^ 3 = 5778 := by
```

**스케치가 만든 서브골**
```lean
theorem h_pow_eq_… (r : ℝ) : r ^ (3 : ℝ) = (r ^ ((1 : ℝ) / 3)) ^ (9 : ℝ) := by
```

**어디가 거짓인가**

`r` 에 대한 아무 조건이 없다. 지수가 실수이므로 `Real.rpow` 가 쓰이고,
mathlib 의 `rpow` 는 음수 밑에서 복소 주분지를 거친다. `r = −8` 을 넣으면

| | 값 |
|---|---|
| 좌변 `(−8) ^ (3:ℝ)` | −512 |
| 우변 `((−8) ^ (1/3)) ^ (9:ℝ)` | 주분지로 −8 의 세제곱근은 1 + √3·i, 실수부만 취하면 부호가 달라진다 |

양수 밑에서는 참인 항등식이지만, 원 문제의 맥락(분모에 `r^(1/3)` 이 있으니
`r ≠ 0`, 그리고 실질적으로 `r > 0`)이 서브골로 전달되지 않았다.

이 문제는 9/10 을 트리 7개로 닫은 최유망 후보였는데, 남은 하나가 이것이었다.
**가장 좋아 보였던 스케치가 가설 하나를 흘려서 무너졌다.**

## 2.3 `aime_1994_p3` — ∀ 가설을 단일 사례로 좁힌 뒤 재일반화

**원 문제 (사람 말)**
> 함수 f 가 **모든 실수 x** 에 대해 f(x) + f(x−1) = x² 를 만족한다.
> f(19) = 94 일 때 f(94) 를 1000 으로 나눈 나머지는? 답은 561.

**원 문제 (Lean)** — 여기서 이미 형식화가 약하다
```lean
theorem aime_1994_p3 (x : ℤ) (f : ℤ → ℤ) (h0 : f x + f (x - 1) = x ^ 2) (h1 : f 19 = 94) :
    f 94 % 1000 = 561 := by
```

`∀ x` 가 아니라 정리 인자 `x` 하나에 대한 가정이다. 이것도 miniF2F 의
형식화 약점이지만, 여기서는 스케치의 반응이 문제다.

**스케치가 만든 서브골**
```lean
theorem hrec_aime_1994_p3 (x : ℤ) (f : ℤ → ℤ) (h0 : f x + f (x - 1) = x ^ 2) (h1 : f 19 = 94) :
    ∀ n : ℤ, f n + f (n - 1) = n ^ 2 := by
```

**어디가 거짓인가**

스케치는 원 문제의 약한 가설을 **강한 가설로 되돌리려** 했다. 하지만
`h0` 는 호출자가 정한 하나의 `x` 에 대해서만 성립한다. 그 하나에서
모든 `n` 에 대한 결론은 따라오지 않는다 — 그 `x` 에서만 식을 만족하고
다른 곳에서는 어긋나는 `f` 를 얼마든지 만들 수 있다.

이것은 거짓 명제라기보다 **도출 불가**다. 그래서 `decide` 류 반증에
걸리지 않는다. 구조적 검사가 필요한 유형이다.

## 4. 왜 스케치 검증에서 안 잡혔나

`verify_and_correct_proof_sketch_with_theorems`
([HILBERTWorker.py:1733](../../src/models/HILBERTWorker.py#L1733)) 가 Lean 에
보내는 것은 다음 형태다.

```lean
theorem mathd_algebra_158 (a : ℕ) … := by
  have hS₁ : (∑ k ∈ Finset.range 8, 2 * k + 1) = 64 := by sorry
  have hS₂ : … := by sorry
  …
```

`sorry` 는 **아무 명제든 증명해주는 항**이다. 따라서
`have h : 57 = 64 := by sorry` 도 완벽하게 타입 검사를 통과한다. Lean 이
확인하는 것은 두 가지뿐이다.

1. 문법이 맞는가
2. 서브골들을 **가정으로 받았을 때** 최종 목표가 도출되는가

거짓 서브골을 가정하면 무엇이든 도출되므로 오히려 조립이 더 쉽게 통과한다.

거짓은 그 서브골을 **실제로 증명하려 할 때** 드러나는데, 그때 Lean 이 주는
신호는 "거짓이다" 가 아니라 **"이 전술로는 안 된다"** 다. HILBERT 는 이를
"아직 맞는 전술을 못 찾았다" 로 해석해 더 깊이 분해하고 스케치를 갈아치운다.
`57 = 64` 를 더 작게 쪼개도 여전히 거짓이므로 영원히 닫히지 않는다.

**"닫히지 않음" 과 "거짓" 을 구분하는 장치가 없다.**

### 5.4 244문제 전체 점검 결과 — 6문제가 같은 결함을 갖는다

`∑` / `∏` 본문이 괄호로 시작하지 않고 최상위에 `+` 또는 `-` 가 있는 문장을
244문제 전체에서 찾았다. **6건이며, 전부 지금까지 한 번도 풀린 적이 없다.**

각각을 Lean v4.16 으로 판정한 결과:

| 문제 | 파싱 후 진리값 | 근거 |
|---|---|---|
| `mathd_numbertheory_343` | **거짓** | `decide`: "proved that the proposition is false" |
| `amc12a_2021_p9` | **거짓** | `¬ (∀ k, …)` 가 증명됨 |
| `mathd_algebra_342` | **거짓** | 가설에서 `a = 28` 이 도출되나 결론은 `a = 42/5` |
| `mathd_algebra_158` | 공허하게 참 | 가설이 모순, 3줄로 증명됨 |
| `induction_pord1p1on2powklt5on2` | 사소하게 참 | `1 + 1/2^k < 5/2` 로 축약 |
| `induction_prod1p1onk3le3m1onn` | 사소하게 참 | `1 + 1/k³ ≤ 3 − 1/n` 로 축약 |

즉 **3건은 증명 불가이고, 3건은 의도한 문제가 아닌 사소한 명제가 됐다.**
어느 쪽이든 HILBERT 가 풀 수 없었던 이유가 설명된다.

#### 세 거짓 문제

`amc12a_2021_p9`
```lean
theorem amc12a_2021_p9 : (∏ k ∈ Finset.range 7, 2 ^ 2 ^ k + 3 ^ 2 ^ k) = 3 ^ 128 - 2 ^ 128
```
파싱: `(∏ k ∈ range 7, 2^2^k) + 3^2^k`. 앞의 곱은
`2^(1+2+4+…+64) = 2^127` 이고(Lean 으로 확인), 뒤의 `3^2^k` 의 `k` 는
자유변수로 암묵 인자가 된다. 따라서 정리는 "모든 k 에 대해
`2^127 + 3^(2^k) = 3^128 − 2^128`" 을 주장하며, `k = 0` 에서 깨진다.

`mathd_algebra_342`
```lean
theorem mathd_algebra_342 (a d : ℝ) (h₀ : (∑ k ∈ Finset.range 5, a + k * d) = 70)
    (h₁ : (∑ k ∈ Finset.range 10, a + k * d) = 210) : a = 42 / 5
```
파싱: `h₀ : 5a + k·d = 70`, `h₁ : 10a + k·d = 210` (두 가설이 같은 자유변수
`k` 를 공유한다). 두 식을 빼면 `5a = 140`, 즉 **`a = 28`** 이다. 결론이
주장하는 `42/5 = 8.4` 와 다르다.

    example … : a = 28 := by simp [Finset.sum_range_succ] at h₀ h₁; linarith
      ✅ 통과 — 가설에서 a = 28 이 실제로 도출된다

sketch6 r1 에서 이 문제에 68시도 · LLM 835회를 썼다.

#### 세 사소한 문제 — 더 흥미로운 쪽

`induction_pord1p1on2powklt5on2`
```lean
theorem … (n : ℕ) (h₀ : 0 < n) : (∏ k ∈ Finset.Icc 1 n, 1 + (1 : ℝ) / 2 ^ k) < 5 / 2
```
의도: $\prod_{k=1}^{n}\left(1 + \frac{1}{2^k}\right) < \frac{5}{2}$ — 곱의 상한을
귀납으로 증명하는 문제.

파싱: `(∏ k ∈ Icc 1 n, 1) + (1:ℝ)/2^k` = `1 + 1/2^k`. 상수 1 의 곱은 1 이므로
곱이 사라지고, `k` 는 자유변수가 된다. 잔여 목표로 확인된다.

    norm_num 후  ⊢ 1 + (2 ^ k)⁻¹ < 5 / 2

이건 세 줄이면 끝난다.

```lean
example (k : ℕ) : (1:ℝ) + 1 / 2 ^ k < 5 / 2 := by
  have h : (1:ℝ) / 2 ^ k ≤ 1 := by
    rw [div_le_one (by positivity)]
    exact one_le_pow₀ (by norm_num)
  linarith
```
    ✅ 통과

그런데 screen57 에서 이 문제는 **depth-0 서브골을 0/1 닫고 실패**했다
(트리 5개). **HILBERT 가 Lean 이 실제로 준 목표가 아니라 사람이 의도한
어려운 문제를 풀려고 했기 때문이다.** 귀납을 세우고 곱의 상한을 다루려
했는데, 정작 Lean 이 요구한 것은 `1 + 1/2^k < 5/2` 였다.

`induction_prod1p1onk3le3m1onn` 도 같다. 잔여 목표는
`⊢ 1 + (k ^ 3)⁻¹ ≤ 3 - (↑n)⁻¹` 이고, `k ≥ 1` 에서 좌변 ≤ 2, `n ≥ 1` 에서
우변 ≥ 2 이므로 성립한다. 이 문제에는 41개 트리를 썼다.

`mathd_algebra_158` 도 같은 성격이다. 가설이 모순이므로 세 줄로 끝나지만,
HILBERT 는 "수학적으로 올바른" 64 − (5a+20) = 4 경로를 따라갔다.

#### 무엇을 뜻하는가

이 6문제는 **miniF2F 형식화의 결함**이고 모델 성능과 무관하다.
244문제의 2.5% 이며, 지금까지 우리가 관측한 모든 실행에서 실패했다.

성능 보고 시 이 6문제를 분리해 적어야 한다. 또한 `results/analysis` 의
기존 실패 분석 중 이 문제들에 대한 서술은 "어려워서 실패" 가 아니라
"형식화 결함" 으로 재분류해야 한다.

괄호를 씌운 수정판을 별도 파일로 만들어 둘 수 있으나, 원본을 고치면
벤치마크 비교가 깨지므로 **기록만 남기고 원본은 유지하는 것**이 안전하다.
